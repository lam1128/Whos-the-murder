# 大侦探群聊开发规则

本目录用于开发“大侦探”的独立 AI 多角色群聊。根目录 `AGENTS.md` 仍是最高规则；冲突时以根目录规则为准。

## 1. 文件边界

- 所有新建、修改、测试和临时文件只能放在本目录内，不得写入本目录外。
- 可以只读参考项目其他目录中的正式资料；引用的源文件不存在时直接忽略，不得猜测或伪造其内容。
- 开始工作前自动查找并读取数字版本最高的 Project Knowledge 和 Game Host Rules。人物及世界补充资料只作补充，冲突时以最新正式 JSON 为准。

## 2. 功能范围

- 群聊是与主线并列的本地模式，不替代主线，也不读取或修改主线存档。
- 群聊使用独立的未来日常时间线：主角已与众人相识约一至两年，关系熟悉、稳定、自然。
- 第一阶段只实现用户、何炅、王鸥三人群聊，但数据结构必须支持以后加入吴昕、撒贝宁和鬼鬼。
- 暂不实现账号、多用户联网、公网部署、语音、图片生成、后台推送、复杂案件或与主线双向同步。

## 3. 设定与人物

- 世界观、身份、职业、能力、关系、称呼和生活方式必须符合最新正式设定；人物均为项目中的虚构仙侠角色。
- 何炅应温和可靠、有分寸，善于接话但不能永远充当主持人。
- 王鸥应温柔清醒、利落简洁，有自己的生活、兴趣和判断，不能只负责照顾或医疗提醒。
- 每个角色必须有独立口吻、判断、状态和发言频率，可以拒绝、不同意、转移话题、彼此接话或因忙碌而不回复。
- 后续角色加入前必须读取其正式档案；资料不足时不得自行补全重大性格和经历。

## 4. 回复与聊天风格

- 根据点名或 `@`、话题相关性、角色当前状态和近期发言量决定谁回复。
- 点名时主要由被点名者回复；未点名时可由一人、两人或暂时无人回复，禁止固定全员轮流发言。
- 角色间可以自然接话，但几条后应停下来等待用户，不能长期排除用户。
- 使用真实即时群聊节奏：消息长短有变化，同一角色可连续发送两三条短消息；避免视觉小说旁白、长篇对白和会议总结。
- 不得替用户说话、行动、决定、承诺、判断情绪或建立感情倾向。

## 5. 时间、状态与内容边界

- 群聊不继承主线章节、Scenario、任务、地点、伤势、选项结果或即时关系状态。
- 可以参考现实中的早晨、中午、下午、晚上或深夜，但不同步现实日期、新闻和社会事件。
- 角色当前活动必须符合职业和世界设定，并在同一段聊天中保持连续。
- 可以生成不影响正史的日常小事，如吃饭、采购、普通委托、临时邀约、小店和群内玩笑。
- 未经用户确认，不得确定恋爱或婚姻、重大承诺、死亡失踪重伤、背叛、离职、重大人生变化、世界灾难、新主线真相或其他重大设定。

## 6. 独立记忆

- 群聊必须拥有独立的聊天记录、角色状态、长期记忆和用户设置，且关闭网页后仍可继续。
- 区分群体共同记忆与角色私人记忆；私人信息不得自动共享。
- 只保存明确偏好、约定、长期玩笑及用户要求记住的内容；不得把随口的错误前提保存为事实。

## 7. 实现与验证

- 采用数据驱动、可扩展的角色注册与回复选择机制，不得写死为两个 AI 角色。
- 只做满足要求所需的最小改动，不擅自扩写人物或主线设定。
- 完成后至少验证：点名路由、非全员强制回复、角色互相接话、人物口吻、状态连续性、本地持久化、长期记忆边界，以及群聊数据与主线存档完全隔离。
- 测试或构建失败时不得宣称完成，应保留错误信息并说明原因。
